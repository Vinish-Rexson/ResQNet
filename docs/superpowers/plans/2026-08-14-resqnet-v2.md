# ResQNet v2 Direct Messaging and Family Circles Implementation Plan

> **For agentic workers:** Execute each task test-first. Commit each reviewed task on the current branch. The user explicitly authorized implementation on `main`.

**Goal:** Extend the existing signed BLE store-and-forward prototype with typed v2 packets, trusted contacts, direct messages, owner-authoritative Family Circles, Circle safety status, delivery receipts, and XML/AppCompat user flows.

**Architecture:** Preserve BLE/GATT, chunk, frame, signed-packet, and relay-envelope responsibilities. Introduce a bounded typed `RQP2` payload whose signed bytes never change across relays, separate raw relay packet storage from authorized application projections, and process targeted/Circle actions through explicit trust and snapshot authorization.

**Tech stack:** Kotlin, Android XML/AppCompat, Room, coroutines/Flow, BLE GATT, Android Keystore P-256 ECDSA, JUnit 4.

## Global Constraints

- Protocol v2 is a clean network break: v1 peers and payloads are rejected.
- Direct and Circle text are authenticated targeted plaintext, not encrypted or described as private.
- Relays validate, deduplicate, store, and forward transport-valid packets but never change signed payload/signature bytes.
- `MeshFrame.Ack` means next-hop persistence only; signed end-to-end receipts apply only to direct and Circle text.
- Public text and transient packets relay for 24 hours with TTL 6; latest Circle snapshot relays until superseded; timely join accepts and leave requests persist until resolved.
- Text is at most 500 UTF-8 bytes, safety notes 160 UTF-8 bytes, names 64 UTF-8 bytes, and a Circle has at most 20 active members including its owner.
- Contacts require nearby discovery plus fingerprint confirmation. Remove/block is local. Blocking suppresses requests/direct visibility only, never public or authorized Circle content, and never relay eligibility.
- Only the Circle owner publishes monotonically increasing membership snapshots. Snapshots list active members only. Invite acceptance activates only through the next owner snapshot.
- Members self-author `UNKNOWN`, `SAFE`, or `NEED_HELP`; higher origin sequence wins. After 24 hours effective status derives to Unknown while retaining the signed last report.
- Removal/dissolution archives authorized history; after local removal no newly arriving Circle text/status is displayed, including delayed older-version packets.
- Room v2 destructively resets Room v1 while preserving SharedPreferences profile and Android Keystore identity; show a one-time notice.
- Visible history is local-only and capped globally at 10,000 messages. No remote delete, read receipts, media, location/maps, SOS, Missing, owner transfer, invite revocation, Wi-Fi Direct, or cloud sync.
